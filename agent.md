# Agent Context: AgentKit SEO Website

This repository contains the public static website for AgentKit SEO, deployed at `https://agentkit-seo.github.io`.

Use this file to get oriented quickly before editing the site. Keep changes factual, crawlable, and aligned with the existing SEO architecture.

## Project Purpose

AgentKit SEO is a human-readable knowledge hub and installable agent skill system for professional profile optimization. The site explains playbooks and skills for:

- CV and ATS optimization
- LinkedIn profile optimization
- GitHub profile and repository SEO
- Web portfolio SEO
- X/Twitter profile optimization
- Agent context file architecture

The site is not just a marketing page. It is also the public documentation surface for the AgentKit SEO methodology, installation flow, provider support, and SEO playbooks.

## Tech Stack

- Framework: Astro
- Rendering: static output
- Deployment: GitHub Pages
- Site URL: `https://agentkit-seo.github.io`
- Sitemap: generated by `@astrojs/sitemap`
- Styling: `src/styles/global.css`
- Content source: Astro content collection in `src/content/playbooks/`

## Key Commands

```bash
npm run dev
npm run og:generate
npm run build
npm run preview
```

Use `npm run build` before finishing meaningful changes. It runs `astro check` and builds static output into `dist/`.

Run `npm run og:generate` after changing skill/playbook names, subtitles, colors, or social preview image content. The generator depends on `rsvg-convert`.

## Repository Map

- `src/pages/`: route files for homepage, docs, providers, contact, skills, playbooks, sitemap, and 404.
- `src/pages/playbooks/[slug].astro`: dynamic playbook page template.
- `src/pages/skills/[slug].astro`: dynamic skill page template.
- `src/content/playbooks/`: Markdown playbooks. Each file becomes a `/playbooks/<slug>/` page.
- `src/content/config.ts`: content collection schema.
- `src/data/site.ts`: canonical site data, authors, navigation, providers, skill metadata, and public routes.
- `src/data/metadata.ts`: canonical URL helpers and JSON-LD builders.
- `src/components/JsonLd.astro`: reusable JSON-LD script renderer.
- `src/layouts/BaseLayout.astro`: shared head tags, Open Graph, Twitter Card, canonical tags, and layout shell.
- `scripts/generate-og-images.mjs`: generates 1200 x 630 SVG and PNG social preview images.
- `public/og/`: generated Open Graph images.
- `public/robots.txt`: crawler policy and sitemap discovery.
- `public/llms.txt`: AI-readable site summary.
- `.github/workflows/deploy-pages.yml`: GitHub Pages build and deploy workflow.

## SEO Architecture

SEO is centralized. Do not hand-edit isolated tags unless there is a clear reason.

Use `src/data/site.ts` for canonical site facts:

- site name
- production URL
- repository URL
- default social image
- description
- authors
- navigation
- provider metadata
- skill metadata

Use `src/data/metadata.ts` for:

- canonical URL generation
- asset URL generation
- full page titles
- `WebSite` JSON-LD
- `Organization` JSON-LD
- `SoftwareApplication` JSON-LD
- `WebPage`, `CollectionPage`, and `ContactPage` JSON-LD
- `TechArticle` JSON-LD for playbooks and article-like pages
- `BreadcrumbList` JSON-LD

Use `src/components/JsonLd.astro` to render structured data. It accepts one object or an array of objects.

## Metadata Rules

For every important public route, keep these aligned:

- visible `h1`
- `<title>`
- meta description
- canonical URL
- Open Graph title and description
- Twitter Card title and description
- JSON-LD `name`, `headline`, or `description`
- social preview image

Important pages should have unique titles and descriptions. Avoid vague labels such as `Home`, `Docs`, or `Project`.

## Structured Data Rules

Use schema types conservatively:

- Homepage: `WebSite`, `Organization`, `SoftwareApplication`, and breadcrumbs where appropriate.
- Index/hub pages: `CollectionPage`.
- Contact page: `ContactPage`.
- Playbooks and methodology pages: `TechArticle`.
- Nested pages: `BreadcrumbList`.

For article-like pages, include dates only when the page supports them through frontmatter or visible page data:

- `datePublished`
- `dateModified`
- `author`
- `publisher`
- `mainEntityOfPage`
- `image`
- `keywords`

Structured data must match visible page content. Do not add schema for reviews, FAQs, products, jobs, events, or people unless that content is genuinely present on the page.

## Playbook Content Rules

Playbooks live in `src/content/playbooks/`.

Each playbook should keep frontmatter accurate:

```yaml
title: "..."
platform: "..."
objective: "..."
status: "draft"
last_updated: "YYYY-MM-DD"
tags: ["..."]
agent_priority: "..."
id: "..."
```

The current playbook files are long combined documents that include multiple internal sections. Preserve their structure unless intentionally refactoring the content model.

When adding SEO guidance, prefer reusable rules and patterns over notes that only describe this website. The playbooks should teach other users how to apply the same method.

Do not invent platform ranking mechanics, hidden algorithm claims, metrics, endorsements, affiliations, or unsupported outcomes.

## Social Preview Images

Social preview images are generated by `scripts/generate-og-images.mjs`.

Generated assets are stored in:

- `public/og/playbooks/<slug>.png`
- `public/og/playbooks/<slug>.svg`
- `public/og/skills/<slug>.png`
- `public/og/skills/<slug>.svg`

The target size is `1200 x 630`.

When editing image text or layout:

- Keep important text inside a safe visual area.
- Make badges wide enough for the longest expected label.
- Check generated PNGs visually after running `npm run og:generate`.
- Keep `og:image`, `twitter:image`, and structured-data `image` aligned.

## Deployment

Deployment runs through GitHub Actions on pushes to `main`.

Workflow:

1. Checkout repository.
2. Install dependencies with `npm ci`.
3. Build with `npm run build`.
4. Upload `dist`.
5. Deploy to GitHub Pages.

Do not edit files in `dist/` directly. `dist/` is build output.

## Validation Checklist

Before finishing SEO or content changes:

1. Run `npm run build`.
2. Confirm changed pages build without Astro errors.
3. If JSON-LD changed, inspect built HTML or use a JSON-LD validator.
4. If social images changed, run `npm run og:generate` and check PNG dimensions or previews.
5. If deployed, validate priority live URLs in Google Rich Results Test, Schema.org Validator, and social preview tools.

## Editing Boundaries

- Preserve existing Astro and CSS patterns unless a change requires otherwise.
- Keep metadata, structured data, and visible content synchronized.
- Do not make unsupported SEO promises.
- Do not add fake testimonials, metrics, clients, awards, affiliations, or platform endorsements.
- Do not remove `rel="me"` identity links unless replacing them with equivalent identity signals.
- Do not change canonical host from `https://agentkit-seo.github.io` without an explicit migration plan.
- Do not manually edit generated OG images without also updating the generator or documenting why.

## Known Notes

The site currently has dedicated playbook and skill pages for six surfaces:

- `agent-context-optimization`
- `cv-ats`
- `github`
- `linkedin`
- `web-portfolio`
- `x-twitter`

The playbook route uses frontmatter dates to expose visible update dates and `TechArticle` JSON-LD freshness fields.

The build may warn about duplicate content IDs in the combined web portfolio playbook format. Treat that as a content-structure issue to investigate separately, not as a reason to remove playbook content casually.
